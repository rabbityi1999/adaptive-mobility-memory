# Project reporting

Maintain `docs/WORK_LOG.md` as the user's canonical working document for this project. Read it before experimental work. After each verified result, material failure, metric or research decision, reconcile the current status and dated change log. Keep original paper metrics, formal reproduction metrics, engineering bring-up and memory-pilot results distinct. Use missing/pending for unrun metrics, not zero. Preserve old results and record settings and evidence for new comparisons.

Before claiming paper alignment, resolve the documented paper/code filtering differences and trajectory-count definitions. A successful code checkpoint alone is not a paper-score reproduction. Do not change the frozen original implementation to force a reported paper count; any alternate protocol needs a separate labeled condition.

Commit and push relevant source, reproducibility instructions and this document to the authorized origin `https://github.com/rabbityi1999/adaptive-mobility-memory`. Inspect exact staged changes, exclude secrets/raw data/weights, preserve unrelated work, never force-push, verify delivery and report failures truthfully. Parent workspace instructions also apply.
