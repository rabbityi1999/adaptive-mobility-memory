2026-10-24，0次模型调用，未选择新目标地点、未冻结新测试集。

东京论文文字筛选流程的7,360名保留用户中，2,409名满足既有“3至50条合格测试session”条件。本轮将早期pilot、检索诊断、ranking拟合／调参与保留队列、四组记忆实验、严格匹配补充、换序实验、两批正式复现的用户统一到同一标识空间，并保守纳入输入中记录的错配供体。跨城市合并排除3,562个唯一身份哈希，其中776名属于东京当前合格用户；剩余**1,633名**，全部存在验证期session。

原始ID字符串无前导零等归一化歧义，使用旧`prepare.digest`规则：`sha256(str(user))[:16]`。在已有两城数据身份集合内未发现哈希碰撞，所有登记排除哈希都能对应源身份；当前2,409名合格用户全部能在旧东京数据中找到。另一段按`split == test`重算的集合检查匹配1,633名结果。递归供体提取、误识别地点ID排除及异常身份格式拒绝检查通过。

初次审计因两个换序`tune_inputs.jsonl`为空停止；检查原换序代码确认其明确写空文件、实际样本放在`fit_inputs.jsonl`。审计随后允许零行文件并记录行数，仍拒绝非空却没有用户的异常文件。失败尝试未生成名单或报告；没有改动既有实验输入。

随后逐类检查供体schema，发现严格匹配补充的`metadata.donor`直接存字符串，其他实验则使用嵌套`donor.user`。补齐字符串格式后增加21个全局排除身份，其中6名属于东京合格用户，最终库存从初版1,639修正为1,633。初版名单仅保存在私有审计目录作为未通过完整供体核验的中间产物，不用于后续选样；最终额外逐行确认100条严格匹配记录的供体均已排除。

## 该库存可以支持什么

可以从中设计与**已登记查询／供体／保留身份**隔离的开发队列。它不是已经选好的测试集，也不是完全未见用户：全城预处理、历史群体统计和图可能使用过这些人的历史。本审计不覆盖未列入来源的其他研究；全时段session数量也参与了合格用户筛选，不能冒充只依赖过去信息的在线入组。

下一步先固定开发查询时间和训练历史截止点、未来评估保留区，以及候选目录／记忆预算。统一历史字段与候选后比较个人单源、群体单源、固定融合；群体历史按查询时刻过滤并排除本人。先检查候选覆盖、可用证据及来源互补，不直接训练路由。是否存在持续习惯变化、是否具备足够检验效能，仍需独立的开发分析；库存数量不能证明这些研究假设。

原始身份名单只留在工作区`research_workspace/agentmove_reproduction/strict_official/development_inventory_20261024/private_users.json`，不上传。公开内容仅为[聚合结果与来源指纹](../reports/development_user_inventory_20261024.json)和[审计代码](../scripts/audit_development_users.py)。不会把这次库存审计记为新预测实验。

复跑使用独立输出文件，输入目录包含原检查点下载的`paper_session_manifest.csv`、`paper_queries.json`和`code_queries.json`：

```powershell
python scripts/audit_development_users.py --pilot /path/to/agentmove_memory_pilot --inventory /path/to/development_inventory --output /new/path/aggregate.json --private-output /private/new/path/users.json
```

脚本拒绝覆盖输出，核验全城session清单指纹。两城缓存只用于身份规范核验；不按新目标地点筛选用户。来源列表是明确范围，不是对所有历史实验的自动完整性保证。
